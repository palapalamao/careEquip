# 03 · 数据结构（FIN / Haystack 记录模型）

> 原则：沿用现有约定——`dm` 前缀标签、记录引用闭合、`dmSynthetic` 标记模拟数据、`dmDataset` 防重放、ID 前缀 `dm-*`。
> 历史数据不自建存储：计量/监测点通过标准 Haystack `his` 机制由连接器写入，本系统只读（hisRead）。

## 1. 现有结构（保持不变）

- site 记录（site 标记）、floor 记录（floor 标记 + siteRef/floorNum）。
- 设备：equip + dmDevice 标记；标签 dmCode/dmModule/dmType/dmSite/dmFloor/dmStatus/dmQuality/dmMetric/dmUnit/dmValue/dmUpdatedAt/dmManufacturer/dmModel。
- 点位：point + sensor 标记 + equipRef + kind/unit + dmQuality/dmValue。

## 2. 设备档案扩展（R1）

设备记录新增可选标签：

| 标签 | 类型 | 说明 |
|---|---|---|
| dmCommissionDate | date | 验收日期 |
| dmInServiceDate | date | 投用日期 |
| dmAcceptanceDocRef | ref → dmDoc | 验收资料 |
| dmEfficiencyClass | str | 能效等级（对应 5.2 设备能效） |
| dmRatedPower / dmRatedPowerUnit | number / str | 额定功率及单位 |

## 3. 档案文件 dmDoc（R1/R2 附件）

| 标签 | 说明 |
|---|---|
| dmDoc 标记 | 记录类型 |
| dmDocType | acceptance / manual / testReport / auditReport / other |
| dmDocDate | 签发日期 |
| dmDocUri | 外部资料地址或文件编号 |

## 4. 运维工单 dmWorkOrder（R2.1）

| 标签 | 说明 |
|---|---|
| dmWorkOrder 标记 | 记录类型 |
| dmDeviceRef | 关联设备（ref，必填） |
| dmWoType | maintenance / repair / retrofit |
| dmWoStatus | open / inProgress / closed |
| dmWoAssignee | 执行人 |
| dmWoScheduled / dmWoStarted / dmWoClosed | dateTime |
| dmWoContent / dmWoResult | 内容 / 结果 |

只增不改；关闭后不再变更（纠错用新记录）。

## 5. 定期检测 dmInspection（R2.2 / 9.1.2）

| 标签 | 说明 |
|---|---|
| dmInspection 标记 | 记录类型 |
| dmInspectTarget | drinkingWater / medicalWater / nonTraditionalWater / medicalGas / hvac / sewage / wasteGas / radiation / indoorEnv |
| dmDeviceRef | 关联设备/系统（可空，指向系统级） |
| dmInspectResult | pass / fail |
| dmInspectDate | date |
| dmReportRef | ref → dmDoc（检测报告） |

## 6. 计量模型（R4 / R5 / R7）

沿用"设备=计量装置"思路：计量表是 equip（可挂 dmMeter 标记），读数是 point。

- 计量表 equip 新增标签：`dmMeter` 标记、`dmEnergyCategory`（lighting / hvac / medicalOffice / elevator / waterSupply / otherPower / waterUse / waterReuse）、`dmMeterScope`（zone / building / dept，配合 siteRef/floorRef 定位）。
- 能耗读数 point：标准 Haystack 约定——电表 `elecMeter`、水表 `waterMeter` + 单位标签（kWh / m³）；历史经 `his` 标记 + hisCollect 由连接器采集，本系统只读。
- 归集维度：site（单体）→ floor/功能区 → dmEnergyCategory → meter equip → point。

## 7. 报警规则与事件（R6）

dmAlarmRule：

| 标签 | 说明 |
|---|---|
| dmAlarmRule 标记 | 记录类型 |
| dmRulePointRef | ref → point |
| dmRuleMetric | 指标（默认 curVal） |
| dmRuleOp / dmRuleThreshold / dmRuleUnit | 如 `> 1000 ppm`（CO2 阈值取标准条文说明） |
| dmRuleSeverity | critical / warning |
| dmLinkEquipRef | 联动设备（如排风机，ref 可空） |

dmAlarmEvent：

| 标签 | 说明 |
|---|---|
| dmAlarmEvent 标记 | 记录类型 |
| dmRuleRef | ref → dmAlarmRule |
| dmAlarmStatus | active / acknowledged / closed |
| dmAlarmValue | 触发值 |
| dmAlarmAckBy / dmAlarmAckAt | 确认人/时间 |
| dmAlarmClosedAt | 关闭时间 |

事件由规则引擎或导入产生；确认/关闭为状态迁移（等价于受控更新，见接口清单）。

## 8. 运行计划（R8）

- dmPlan：`dmPlanSystem`（medicalGas / elec / hvac / water / steam / heating）、`dmPlanPeriod`（年/月）、`dmPlanContent`。
- dmPlanExec：dmPlanRef + 执行日期 + 执行结果 + 年度考核结论 dmPlanReview。

## 9. 审计 / 绩效 / 可再生（R5）

- dmAudit：dmAuditScope、dmAuditDate、dmAuditConclusion、dmRectifyWoRef（整改工单 ref，可空）。
- dmKpiSnapshot：核算单元 + 周期 + 能耗汇总 + 同比百分比（可由读数计算，快照仅为报表留痕）。
- dmRewardRecord：奖惩登记（关联 dmKpiSnapshot）。
- dmRenewableUse：类型（solar 等）+ 周期 + 利用量。

## 10. 自评评分项（R9，P2）

- dmScoreItem：条款号（如 9.2.8）+ 自评分 + 证据 ref（→ 工单/检测/审计等记录）+ 说明。

## 11. 通用约束

- 所有新记录带 dmDataset（如 `deviceManager-demo-v2`）与 dmProvenance；模拟集全部加 dmSynthetic。
- 引用必须闭合；枚举值集中定义在 fixtures，前端与 seed 共用。
- 真实数据（连接器写入的 his）不带 dmSynthetic；界面需区分来源展示（沿用现有 source 标记）。
