# 05 · 架构设计（前端 / 后端）

## 1. 总体架构

```
FIN 平台（宿主）
 ├─ 连接器/采集：写入 point curVal + his（本系统不实现，只读）
 ├─ deviceManager POD
 │   ├─ res/web/dm     前端 React 应用（新增页面与 provider）
 │   ├─ lib (Fantom)   只读信息 + 受控写函数（dmCreateWorkOrder 等）
 │   └─ ext            扩展注册（不变）
 └─ 记录库：equip/point/工单/检测/计量/报警/计划/审计 等 Haystack 记录
```

不引入独立后端服务；读全部走 FIN 会话，写走 lib 函数（见接口清单）。本系统保持"观察 + 记录型写入"，不做设备控制闭环。

## 2. 前端（ts/）

- 技术栈不变：React 19 / Vite / React Router 7 / Recharts 3。
- 路由新增：`/workorders`、`/inspections`、`/energy`、`/energy/yoy`、`/audits`、`/environment`、`/alarms`、`/plans`、`/assessment`；设备详情新增档案与运维时间线标签。
- provider 层（`ts/src/data/provider.js`）：每个接口定义 local / fin 双实现，签名与 `04-接口清单.md` 一一对应；fin 实现经 haystack-nclient 宿主会话，历史经 hisRead。
- fixtures（`ts/src/data/fixtures.js`）：枚举（工单类型/检测对象/报警严重级/计划系统/分项类别）唯一来源，seed 脚本与前端共用。
- 组件：新增 WorkOrderTable、InspectionForm、EnergyBreakdown（分区→分项→点 下钻）、YoYChart、AlarmCenter（确认/关闭操作）、PlanBoard、DeviceTimeline。
- 沿用既有体验约束：错误/空/未知态、来源标注（synthetic vs 真实）、桌面+移动布局、键盘导航、CSV 导出。

## 3. 后端（FIN POD）

- `fan/DeviceManagerLib.fan`：新增写函数（I-W1…I-W8）。每个函数：参数校验 → 冲突/防重放检查 → diff(null, rec, {add}) 或受控状态迁移 → 返回记录 id。异常抛错不静默。
- 种子脚本：`scripts/seed-data.mjs` 扩展生成新记录类型（`deviceManager-demo-v2`），仍走"confirmed=false 预览 + 用户确认"流程；防重放沿用现有 dataset 冲突拒绝。
- 历史数据：不自建采集；计量/监测点的 his 由现场连接器提供。模拟模式下用 fixtures 生成确定性历史曲线（标注 Synthetic）。

## 4. 数据流示例（能耗同比）

1. 前端 provider.fetchEnergyYoY(scope, period) → fin 实现组装 readAll(dmMeter)+hisRead 两周期数据。
2. lib 可选提供 Axon 聚合函数（数据量大时减少往返；P1 先前端聚合，够用再上）。
3. 前端 YoYChart 渲染，>10% 下降高亮；结果可另存 dmKpiSnapshot 留痕。

## 5. 构建与验证

- 沿用 `scripts/build.ps1`：npm ci → 单测 → seed 预览 → 离线 Axon 解析 → 构建 → 资源哈希核对。
- 新增单测：provider 双实现等价性（同 fixtures 输入同输出）、工单状态机合法性、报警迁移合法性。
- e2e（Playwright）：工单创建→时间线可见；CO2 超限→报警事件→确认关闭；同比页空态/错误态。
- 边界声明：编译与离线解析不证明现场扩展启用；现场验收另行列项。
