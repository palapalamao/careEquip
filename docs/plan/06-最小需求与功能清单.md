# 06 · 最小需求与功能清单（最能体现标准核心思想的两个功能）

> 从 v2 计划（01~05）中选取的两个功能：R-A 抓"控制项底线"（医院安全运维），R-C 抓"运行管理闭环"（计划-执行-考核）。
> R-B（室内环境质量监控与报警联动，8.2）确定由 DDC 层完成，不在本系统实现。
> 数据结构与接口**完全复用** 03/04 已有定义，本清单只做选取与裁剪，不新增定义。

## 为什么选这两个

1. **R-A 对应标准的"底线"**：9.1.1/9.1.2 是控制项，不满足即失去参评资格。条款里的检测对象（医用气体、医疗用水、射线防护、污水处理）是医院独有的——这正是"绿色医院"区别于普通绿色建筑标准（GB/T 50378）的地方：**先保医疗安全，再谈绿色**。
2. **R-C 对应标准的"管理闭环"**：9.2.6 要求对医用气体、电力、空调、供水、蒸汽、供热等系统制定科学合理的运行计划，并**每年对执行情况进行考核**（3+2 分）。它与 R-A 正好拼成完整链条——**R-A 是事后留痕（记录），R-C 是事前安排 + 年度考核**；"有计划、有执行、有记录"是第 9 章「运行管理」的核心评价逻辑，也是本系统作为设备管理工作台的直接延伸。

## R-A 设备运行维护证据链（9.1.1 控制项 / 9.1.2 / 9.2.9）

- R-A.1 设备档案：验收日期、投用日期、验收资料引用（= R1.1）。
- R-A.2 维护工单：创建→执行→关闭，留痕不可删（= R2.1/R2.3）。
- R-A.3 定期检测记录：检测对象含饮用水/医疗用水/医用气体/空调/污水/射线防护/室内环境，结论达标/不达标，附报告（= R2.2）。
- 验收：任抽一台设备，档案完整、时间线含全部工单与检测记录；重复提交被拒绝。

**功能 F-A 设备档案与运维记录**
- 页面：设备详情新增「档案」「运维记录」标签；新增 /workorders、/inspections 两个列表页。
- 数据：03 §2 设备扩展标签、§3 dmDoc、§4 dmWorkOrder、§5 dmInspection。
- 接口：I-R1、I-R2、I-R3、I-R4；I-W1、I-W2、I-W3、I-W4。

## R-C 运行计划管理（9.2.6，5 分）

- R-C.1 按系统制定计划：医用气体/电力/空调/供水/蒸汽/供热，支持年度/月度计划（= R6.1）。
- R-C.2 执行登记：每次执行记录日期与结果（完成/部分完成/未完成）（= R6.2）。
- R-C.3 年度考核：按系统汇总年度执行情况，给出考核结论并可导出。
- 验收：为空调系统创建月度计划，登记两次执行结果，生成年度考核汇总。

**功能 F-C 运行计划与执行考核**
- 页面：/plans（计划列表+创建、执行登记、年度考核汇总视图）。
- 数据：03 §9 dmPlan、dmPlanExec。
- 接口：I-R11；I-W8。
- 与 F-A 的衔接：执行中发现的设备问题可转入 F-A 工单（页面提供"转工单"入口，写入 dmWorkOrder，引用同一设备）。

## 裁剪说明（本最小清单不做的）

- R-B（IAQ 监控报警，8.2）：由 DDC 层完成，本系统不实现。
- F1.4 实时值接入不单列：F-A/F-C 不依赖实时数据，实时/历史（I-R5/I-R6）随后续环境监测类功能再做。
- 用水节水（F2.3）、自评表（F3.2）不在最小范围内，后续按 02 清单追加。
- 能耗类维持暂缓（见 00 差距分析 2.3）。

## 交付顺序

1. F-A 先行（控制项，门槛价值最大，纯记录型功能，无外部数据依赖）。
2. F-C 随后（数据结构与 F-A 同级，含"转工单"衔接，依赖 F-A 已落地）。
